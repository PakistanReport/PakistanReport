# Pakistan Report sourcing standard — adopted for new articles

Use original reporting prose, clear inline attribution and direct evidence links for consequential claims, plus a compact Sources section where appropriate. The accompanying article pattern is a draft scaffold, not publishable copy. Plain-text front matter: title, description/standfirst and image_alt. Current layout renders description as standfirst; do not add an unsupported standfirst field.

Trace material claims to specific inspected releases, documents, court orders, filings, datasets or job listings. Record issuer, exact title, URL or document reference, publication/effective/reference dates, retrieval time and claim/page/table locator in a private ledger. State limitations. A source can prove a statement was made without proving the statement true. Verify figures, units, periods, names, quotes and procedural status. Social media ordinarily supplies a lead. Corroboration must be independent rather than multiple copies of a release.

Attribute another newsroom's original reporting and do not imply Pakistan Report conducted it. If original evidence is inaccessible, document that limitation and obtain the appropriate review before using qualified secondary reporting. Do not invent evidence links or checked dates. Sources lists must contain evidence actually used.

Level 1: straightforward primary-source releases/jobs after factual and publishing QA. Level 2: complex economics, major business/world developments and explainers require editorial review. Level 3: disputed politics, court/crime, casualties, defamatory risks and sensitive breaking developments require human approval of the exact version. The highest applicable level governs regardless of category.

This folder is excluded from Jekyll output, but a public GitHub repository would still expose its files. Never store private identities, confidential evidence, credentials or actual private approval logs in it. Keep real claim/review ledgers in a separate private location.

New-article checklist: source ledger complete; claims verified; originals written; inline evidence links and Sources section appropriate; risk/approval recorded privately; no placeholders; dates truthful; plain-text metadata; descriptive image alt; rights/illustration caption correct; relevant internal links selected; actual build and live QA pass before distribution.

To use the pattern: copy outside this folder as a draft, replace all placeholders and source URLs with verified content, choose the existing category spelling (Explainer is singular internally), select a stable filename/permalink and actual Pakistan time, complete review, and only then remove `published: false`. The `.template` suffix and excluded folder keep the sample out of the site. Do not bulk-convert current articles.

The zero-story Explainers section is an editorial gap. Commission a useful evidence-based answer to a real reader question; do not generate filler or relabel stories to inflate counts.
